# User mentions

Typing `@` opens a searchable picker in the main/mini global chat, direct and group chat composers, and feed post composer. Selection inserts the actual username; multiple names can be added, including usernames containing spaces. Arrow keys, Enter/Tab, Escape and touch are supported. Enter selects a suggestion instead of sending the message. The picker only exposes conversation participants in private/group contexts.

Only the exact existing `Emirgan` account can broadcast with `@herkes` (`@everyone` is also recognized). Neither a generic admin role nor a client-supplied flag grants broadcast permission. Normal users can mention individual people. Manual text is independently resolved against actual user records on the server; username-prefix and email-like matches do not produce mentions. Authors do not notify themselves. Private/group recipients must belong to the conversation; broadcast never exposes a closed conversation to outsiders.

Receipts live in the additive `mentions` table, keyed by content kind, persisted content ID and recipient. Atomic batched receipt/notification inserts prevent repeated usernames or retries from sending duplicate mention notifications. Mention notifications use existing authenticated per-user Socket.IO rooms and device push infrastructure. They carry structured metadata so both notification-list items and floating toasts open the exact tagged content in an accessible dialog, including older content. Deleted content and revoked group membership display an unavailable message. No message text is included in broadcast ID-confirmation events; group ID confirmations only go to member rooms.

Recipients initially see an amber highlight. Intersection observation plus a 1.8-second dwell while the page is visible and focused marks the receipt seen; opening the chat, an offscreen element or a background tab is insufficient. Seen receipts retain a subtle highlight and survive reloads. Seen changes synchronize to the recipient's other connected devices. The initial receipt cache is scoped to the authenticated account and the most recent 2,000 mentions; older receipts remain stored. Notification read state is independent of the content's seen state, so clicking a notification does not prematurely dim unseen content.

Run `npm run test:mentions` and `npm run test:mentions:browser`. Validation includes three service/socket test groups (exact recipients, ordinary-user broadcast rejection, deduplication, owner isolation, revoked membership, durable seen state, final global/DM message IDs); real browser checks at desktop and touch/mobile widths (multi-name picker, post textarea, keyboard selection, background/offscreen gating and preview); ten DM regression tests and the existing two-session desktop/mobile DM browser suite. TypeScript and production build also pass. A pre-existing upstream debug display accessed Socket.IO's private `Manager.uri` property; a narrow read-only type assertion fixes that compile error without changing endpoint selection.

Deploy normally; initialization creates the table/index without resetting messages or notifications. Physical OS push delivery depends on the site's existing push subscription and permission setup; tests exercise the delivery integration with test transports, not real user devices.
